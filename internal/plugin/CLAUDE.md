# internal/plugin — package map

**Version note:** everything in this file describes the **live v1.1 substrate** (HashiCorp go-plugin subprocesses, gRPC over UDS — ADR-041). The MCP 2026 realignment (ADR-053…ADR-060, target `v0.2.0-alpha`) replaces this substrate outright with signed containerized MCP servers, but is **built-in-parts, NOT cut over** — the container substrate (milestone #15) and the host-endpoint skeleton (#875) are merged yet not live, so this substrate is still what runs; its spec is `docs/developer/mcp-realignment-spec.md`. Do not mix the two: code changes here target v1.1 semantics until the cutover lands.

Moved from the root CLAUDE.md `Key packages` entry (2026-07-31); loads when working under this package. Plugin-scoped settled decisions (ADR-041…ADR-052) are summarized in the root CLAUDE.md and in full in `docs/developer/settled-decisions.md`; the substrate spec is `docs/developer/plugin-system-spec.md`; plugin admin endpoint contracts are in `.claude/rules/plugin-admin-api.md`.

```
  plugin/             — host-side plugin loader. Implements fsnotify watcher, tarball extractor, minisign verifier, DB installer, and subprocess lifecycle (process/). Per-instance UDS is provided transitively by go-plugin's broker. Identity tokens are issued at spawn via `internal/plugin/identity` and delivered to the subprocess via the `GLEIPNIR_INSTANCE_TOKEN` env var (constant `serve.InstanceTokenEnvVar`); the SDK's outgoing-metadata interceptor reads the env and attaches the token to every host RPC, where `hostsvc.UnaryInstanceTokenInterceptor` validates it. Phase 4 substrate (subprocess spawning #291, per-instance identity token #292, generation refcounts #294, hostsvc activation #295) is complete; remaining Phase 5 work tracked under #159 covers ChannelService and admin UI surfaces, not the host-RPC plumbing.
    state/            — per-instance health-state machine; mirrors execution/runstate (transition table + version-CAS, ADR-038). Severity ranking encodes §8.1 "plugin can only mark itself worse" merge rule.
    manifest/         — host-side manifest diff (material vs cosmetic) consumed by the loader on hot-reload (spec §5.4). Schema-shape comparison strips `description`/`default` keys at every depth; depends only on plugin-sdk/manifest + stdlib.
    tools/            — plugin-side tool registrar; reserves `<instance>.<tool>` names with `internal/toolregistry`, writes `plugin_tool_namespace_conflict` audit events on collision, drives the instance to `unhealthy` (issue #194), and tracks per-instance generation consulted by `internal/execution/agent` to fail tool calls bound to a replaced generation with a structural error (issue #195, ADR-018).
    identity/         — leaf package; in-memory `(token → instanceID)` registry that authenticates plugin Host RPCs (spec §8.4, issue #202). `Issue(instanceID)` mints a 256-bit base64url token and atomically auto-revokes any prior token for the same instance — a killed-generation token cannot impersonate the new generation. `Lookup(token)` returns the stable instance ID; `Revoke`/`RevokeInstance` cover subprocess-exit and uninstall paths. No internal imports.
    audience/         — audience composition. `Resolve(rows)` materialises an audience's effective entry list and auto-appends a synthetic `gleipnir.in-app` entry (`Auto:true`, lowest priority) unless `disable_in_app_fallback=true`. `ValidateAudienceCoverage` rejects an opt-out save when no other Request-capable entry exists. Synthetic entry is materialised at read-time only — never persisted in `audience_entries`. `Dispatcher.Request` returns `(requestID, RoutingOutcome, err)`: `RouteToPlugin` for persisted entries (writes `plugin_pending_requests`), `RouteToInApp` for the synthetic entry (no DB row; agent-side caller routes via the existing `inAppChannel`).
    binding/          — leaf package (stdlib + yaml.v3 only); runtime evaluator for subscribed-trigger bindings (spec §7.3, issue #217). `Compile(binding map[string]any, schema *yaml.Node)` resolves the operator per field from the manifest's `binding_schema` (Option C — `type:string,format:regex` → regex, `format:contains` → contains, plain `type:string` → equals, field `mention_only` + `type:boolean` → mention-only) and pre-compiles regexes; `(cb).Evaluate(payload map[string]any)` is pure bool/error with implicit AND across keys. Missing payload field or type mismatch is silent (no-fire, not an error) — plugins are external; a runtime error should not crash the dispatcher. `format:glob` is reserved for future use (`ErrUnsupportedOperator`). Nested binding paths and OR semantics are v2. The "Option C" schema-shape operator resolution described above is the current (pre-ADR-052) scheme. ADR-052 (decided, post-1.1) moves operator selection from schema-shape to a per-policy explicit op: a field will advertise an allowed-operator SET and the binding value gains an optional `{op, value}` object form (flat value = author default op, for back-compat); `Compile` will resolve `Op` from the explicit `op` when present rather than solely from `type`/`format`. Not yet implemented — see ADR-052 follow-ups.
    configvalidate/   — generic plugin-config validator built on `santhosh-tekuri/jsonschema/v6`. Compiles a manifest's reflected `config_schema` (YAML) once per content-hashed snapshot and surfaces field-level errors as `[]FieldError{Field, Message}` for the upcoming audience save endpoint (#290) and reused by trigger-binding (#216) and instance-config (#241) validation. `ForChannelAudience` rejects manifests without a `ChannelService` (`ErrNotChannelPlugin`); `ForTriggerBinding` linear-scans `EventKinds` (no [0]).
    dedup/            — rolling-window event-dedup for at-least-once plugin substrate events (#562). `Store` interface with `Seen(ctx, Key) (bool, error)`; `dbStore` is the SQLite-backed production implementation (INSERT ... ON CONFLICT DO NOTHING `:execrows` maps 0-rows-affected to "already seen"). `Sweeper` runs a background ticker that evicts `plugin_event_dedup` rows older than the fixed 1-hour TTL via `SweepEventDedup`. Both types take an injected clock for deterministic testing. `Noop` (always returns false) is retained for tests that don't need dedup semantics. Wired at `pluginruntime.go` site 1 (sweeper under `rt.bgWG`) and site 2 (`Dedup: dedup.NewDBStore(...)` in the trigger dispatcher).
    trigger/          — host-side subscribed-trigger plumbing (issue #214). `Supervisor` opens the long-lived `TriggerService.Start` server stream per instance (single drain goroutine — per-stream ordering preserved), restarts on EOF/error with bounded exponential backoff + ±25% jitter, and reports health via the Manager's HealthSetter. `Dispatcher.Handle` consumes `EmittedEvent` from the hostsvc trigger sink: dedup check (`dedup.Store`), scan `GetSubscribedActivePolicies`, compile binding from the plugin's manifest `event_kinds[].binding_schema`, evaluate against payload, launch matching policies via `RunLauncher.LaunchWithConcurrency` (the shared launch seam; mirrors cron/poll, not the HTTP-coupled `internal/trigger/launch.go`). `SinkAdapter` lives here to break the hostsvc↔trigger cycle. Late-bound into `hostsvc.Server` via `SetTriggerSink` after `RunLauncher` is constructed in main.go. Event delivery is unified on the `EmitEvent` Host RPC (issue #495, spec §4.3): both the SDK ergonomic `emit(trigger.Event)` callback (`serve.NewTriggerServer`) and the raw Slack reference emit via `host.EmitEvent`; the `TriggerService.Start` response stream carries NO events and is only a liveness channel. `Supervisor.recvLoop` still dispatches a stray `StartResponse` defensively (deprecated path) but the SDK and reference plugins never produce one.
    dispatch/         — gRPC tool-call dispatcher over UDS to plugin instances; per-call deadline matches `GLEIPNIR_MCP_TIMEOUT`, per-instance concurrency semaphore + bounded queue gate (spec §13.2/§13.6), and run-cancellation fan-out via `Cancel(call_id)` with 5s deadline + force-disconnect fallback (spec §13.8, issue #198). Wired into the agent fork point through `agent.PluginToolDispatcher`; receives cancel hooks from `internal/execution/run.RunManager`.
    process/          — per-instance subprocess lifecycle. Thin wrapper around plugin-sdk/hostwire (HashiCorp go-plugin) that adds identity-token issuance, per-instance env injection (GLEIPNIR_INSTANCE_ID / GLEIPNIR_PLUGIN_ID / GLEIPNIR_INSTANCE_TOKEN), per-instance log labels (plugin= / instance=), and graceful Stop / crash health callbacks. Imports plugin-sdk/hostwire, plugin-sdk/serve (for `InstanceTokenEnvVar`), internal/plugin/identity, and internal/infra/logctx. Manager (manager.go) imports internal/plugin/state to build the HealthSetter callback; the core process.go / waitForExit logic drives health state only via an injected callback, never importing the state package directly. `Manager.ReloadInstance` (issue #294) drives a generation rotation: `BeginDrain` → `stopWithoutUnregister` → `Start`; `ManagerConfig.GenerationController` is optional and nil-safe so non-plugin code paths keep working.
    generation/       — leaf package (stdlib-only); per-(instance_id, generation) refcount + drain controller for plugin Host RPCs (spec §8.4, issue #294). `Controller.RegisterInstance` is idempotent and never resets the counter. `Acquire(ctx, instanceID)` increments the refcount under the current generation and returns a wrapped cancellable context; new traffic is held in `Unavailable` (caller-deadline-bounded) while a drain is in progress. `BeginDrain(ctx, instanceID, grace)` bumps the generation, waits for old-gen refcount to reach zero within `grace`, then force-cancels stragglers via the wrapped contexts (mirror of dispatcher's §13.8 5s force-disconnect, but via `context.CancelFunc` rather than `conn.Close` because host RPCs are ordinary unary handlers that respect ctx). `UnregisterInstance` wakes any blocked `Acquire` callers. Concurrent `BeginDrain` callers serialise: the second returns `"drain already in progress"`. Generation type is `uint64`; this counter is independent of `internal/plugin/tools.Registrar.Generation` (`int64`, different epoch).
    hostsvc/          — host-side gRPC server for plugin→host RPCs (spec §8.1/§8.2/§8.5, issues #199 + #200 + #201). `UnaryCallIDInterceptor` reads the `gleipnir-call-id` metadata into context; `RejectIfDetached` is preserved for future RPCs that require call-scope binding; `WriteAuditStep` instead authenticates via request-ownership per spec §8.5 (the request_id's `plugin_pending_requests.plugin_instance_id`, or the native `feedback_request`'s policy-grant by stable instance name), so substrate-initiated callbacks (e.g. Slack Socket Mode click events) do not need to synthesize a call_id. `Server` implements the eight always-on Tier-1 RPCs (`GetInstanceConfig`, `GetCredentials`, `GetRunContext`, `WriteAuditStep`, `EmitMetric`, `EmitEvent`, `Log`, `SetHealthState`); resolves `(run_id, policy_id)` from the propagated `call_id` via `dispatch.Pool.LookupCall`; reuses `internal/infra/{logctx,metrics,event}` rather than parallel systems. `EmitMetric` force-prefixes `gleipnir_plugin_`, auto-injects `plugin`/`instance` labels, enforces a 100-distinct-values per-(metric,label-key) cardinality cap, and rejects inconsistent label-key sets (no panics from `GaugeVec.With`). `WriteAuditStep` accepts only `feedback_response` step type — anything else writes an `unauthorized_step_type` audit event. Tier-2 RPCs `RunHistoryRead` and `UserDirectoryRead` are gated by the manifest's `tier2_capabilities` list; an undeclared capability returns PermissionDenied + an `unauthorized_tier2_call` audit event. `RunHistoryRead` is scoped to policies that reference the calling instance via tool grants (`<instance>.<tool>` prefix in `capabilities.tools`); `UserDirectoryRead` returns only `(user_id, username, role)` tuples — no credentials or session data. `UnaryInstanceTokenInterceptor` reads `gleipnir-instance-token` metadata, looks the token up in `internal/plugin/identity.Registry`, and attaches the resolved instance ID to the request context for `contextBinder` to read; missing/unknown tokens are rejected with `codes.Unauthenticated` before the handler runs (spec §8.4, issue #202). `WriteAuditStep` additionally enforces that a `feedback_response`'s `request_id` belongs to the calling instance: it walks `feedback_request → run → policy.yaml` and rejects with `unauthorized_request_id` (severity high) when no `<instance_name>.<tool>` capability prefix is granted — the check is by stable instance name so it survives generation rotation. `WriteAuditStep` also carries an optional `actor_external_id` (the acting Slack `user.id`); when set, the host resolves it via `GetUserBySlackUserID` (the `users.slack_user_id` admin-managed mapping, joined to `user_roles`, deactivated users excluded) and authorizes the resolution only when the mapped user holds `approver`/`operator`/`admin` — otherwise it returns `{unauthorized:true}` WITHOUT resolving (request stays open), writes an `unauthorized_approval_attempt` audit event (severity high), and the plugin posts an ephemeral to the clicker. Empty `actor_external_id` is a passthrough for non-external callers (#624; global role gate — per-audience allowlist deferred). `UnaryGenerationRefcountInterceptor` (issue #294) chains after the token interceptor and routes each RPC through `internal/plugin/generation.Controller.Acquire`/`Release` so a generation rotation can drain in-flight calls before the new generation accepts traffic. `hostsvc.Server` is constructed once at boot in `main.go`, attached to every subprocess via `Manager.HostServerFor`, and gated behind the `[token, generation, call-id]` interceptor chain plumbed through `hostwire.Options.ServerInterceptors`.
    hostendpoint/     — **MCP realignment (ADR-057 as amended, spec §8), #875.** The host-side MCP server managed plugins call for server→host callbacks — the replacement for hostsvc's gRPC plane, which stays live until the cutover (#883). Skeleton only so far: `Server` serves modern-only `server/discover` (A4 header + A1 `_meta` enforcement mirroring `internal/mcp`'s FakeMCPServer, the transport oracle; legacy `initialize` is method-not-found because every plugin that can reach this listener ships against the realignment contract), reporting the endpoint's own ADR-042 SemVer (`Version`) via `_meta` serverInfo. `ListenerSet` runs one listener per instance network and refuses wildcard binds structurally (`ErrWildcardAddr`) — "internal networks only" must not depend on caller discipline. `AssertHostPlane` enforces the host-plane invariant at boot (main.go refuses to start): no `host/…` tool name in `internal/toolregistry`, because everything there is grantable and a grantable host tool is an ADR-001 break. The `host/` prefix is what makes the assertion exact — bare short names (`log`, `get_credentials`) are legitimate plugin tool names, and `/` never appears in a dot-name tool part. Tool inventory (`ToolNames`) is declared ahead of its handlers so the assertion guards the full §8 set from the first boot; handlers and the SDK client are #877–#882. Middleware (#876) ports the three gRPC interceptors with semantics unchanged, chained token → generation → call-id via `Chain` (a ListenerSet should always be constructed with `Chain`; a bare `Server` is a host endpoint whose every caller is anonymous): `RequireInstanceToken` reads the spec §8 bearer header and rejects 401 BEFORE the handler (missing vs unknown kept as distinct messages; resolver errors are 500, not 401 — a DB fault must not read as a bad credential); `TokenResolver` has two implementations, one per substrate era — `RegistryResolver` over the v1.1 `identity.Registry` (per-instance, `Generation` 0) and `GenerationTokenResolver` over `GetContainerGenerationByTokenHash` via `reconciler.HashInstanceToken` (per-generation; a DRAINING generation still authenticates because tokens revoke at retire, not switch — #813 — and a revoked one cannot, enforced by the query itself); `RequireGenerationSlot` acquires a `generation.Controller` slot before the handler and releases after, so a rotation drains in-flight host-endpoint calls exactly as it drained gRPC ones (in-flight = force-cancelled via the wrapped ctx after grace; new-mid-drain = blocks then 503 on own deadline; unregistered instance = 503; no-identity passes through so a mis-composed chain surfaces the auth error); `WithCallID` attaches an unambiguous `Gleipnir-Call-Id` to ctx and never rejects — run/policy logctx enrichment stays handler-level, as in hostsvc today. hostsvc's `RejectIfDetached` is deliberately NOT ported: its only prospective consumer, WriteAuditStep, leaves the inventory entirely (#880). Tier-1 methods (#877, `tier1.go` + `toolcall.go`): the six kept methods are MCP tools dispatched via `tools/call` behind the chain — transport faults are JSON-RPC errors, handler refusals are `isError` results carrying hostsvc's stable code strings (`cardinality_cap_exceeded`, `unauthorized_request_id`, …) so a migrating plugin matches the same identifiers. `Register` refuses any name outside `ToolNames()` (a tool the boot assertion never guarded must not be mountable). `host/emit_metric` runs the ADR-047 guard now extracted to `internal/plugin/pluginmetrics` (shared with hostsvc's gRPC path until #883 deletes it). `host/set_health_state` is PER-CAPABILITY (#814's model, the fix for one-scope-marks-all-unhealthy): it records into `caphealth.Registry.SelfReportCapability`, which applies §8.1 worsen-only per capability under the registry lock — an improvement report is `{ok:true, applied:false}`, recovery is host-observed (prober / `ClearCapability`), and the plugin-reportable vocabulary is exactly healthy|unhealthy (circuit_broken and the pending_* family are host/admin verdicts a plugin must not assert). `host/get_run_context` keeps the ownership check AND its high-severity `unauthorized_request_id` audit event — a foreign call id must not read another instance's run context. `host/get_credentials` keeps its reason-to-exist comment: header injection cannot cover streams. Not wired to real instance networks yet — the reconciler drives `Add`/`Remove` when the substrate goes live.
    e2e/              — host-side substrate composition tests (issue #237). Exercises the real audience → binding → dedup → trigger → dispatch path against an in-process stub plugin so the host+plugin composition is gated per-PR without spawning a real plugin binary. External test package (`package e2e_test`); registers a gRPC `TriggerServiceServer` directly on `127.0.0.1:0` mirroring `internal/plugin/trigger/supervisor_test.go`. No Slack-specific code — Slack-shaped scenarios are covered by the nightly Playwright spec at `tests/playwright/slack-kitchen-sink.spec.ts`.
    loader/           — v1 install pipeline (extract → verify → snapshot), plus the **v2 OCI bundle path** (ADR-056, spec §7 bundle format; `ocibundle.go` + `ociinstall.go`, #808). A v2 bundle is the same Minisign-signed drop-in tarball, now carrying a v2 manifest and an `image.tar` OCI archive instead of a Go binary; `manifestv2.IsV2` routes between the two so a v1 tarball reports "old format" rather than a pile of unknown-field parse errors. The signature covers (archive, manifest), the same pairing v1 used for (binary, manifest) — editing the manifest to point elsewhere breaks it, which is what makes the digest pin meaningful rather than self-asserted. `OCIInstaller` reuses the v1 `Installer` for everything ADR-045 settled (verifier, TOFU pin check, audit, tx helper): "the trust model is unchanged" is only true if it is literally the same code. Ordering is load-bearing — image load and digest verification happen BEFORE any row is written, so a rejected bundle leaves the DB untouched (#349). Manual posture is detected by `ErrManualModeWrite` from the runtime rather than a flag, so the posture enforces itself; the install still commits and records `plugin_image_load_skipped` at high severity. `binary_path` stays NULL for v2 rows on purpose (the v1 subprocess manager re-spawns from it), which is also why the SBOM endpoint does not yet serve v2 — it resolves the file relative to `binary_path`, and a real answer needs a bundle-path column belonging to the plugins-row cutover.
    reconciler/       — **MCP realignment (ADR-056, spec §7), not part of the live v1.1 substrate.** Level-triggered convergence loop over `internal/plugin/container`: each pass lists managed containers by label (`gleipnir.managed=true`), diffs them against the `plugin_containers` desired-state rows, and takes ONE step per instance (create → start over two passes; stop-then-remove for an orphan over two more). `plan.go` is a pure planner (`planFor`/`planPass`) so the whole convergence table is testable without a runtime or a store. Identity comes from container LABELS, never a stored container ID — that is what makes crash-resume free: the loop keeps no state between passes, so a new process picks up wherever the world is. Image/config-hash drift on a running container is REPORTED (`ActionDriftDetected`) and not acted on; replacing a running container is a generation rotation, which is a separate issue. `container.PostureManual` makes `Start` inert rather than relying on an empty diff — a manual-mode container carries no desired row, so a running loop would read it as an orphan. Trigger model is periodic ticker + non-blocking `Kick()` (coalescing, buffered at 1); `Start`/`Wait`/`Stop` mirror the Poller so the drain machinery can join it. Publishes `container.reconcile_pass` after every pass (the signal-don't-poll synchronization point). `subnet.go` owns per-instance network address space: `SubnetAllocator` carves one `/24` per instance out of `GLEIPNIR_PLUGIN_SUBNET_POOL` (default `10.83.0.0/16` = 256 instances) using `netip`, allocating densely (lowest free slot, so a removed instance frees its number) and idempotently. Race-safety is the DB's: allocation is a bare INSERT behind `UNIQUE(pool_base, slot)`, so the read-then-write gap is safe and losing is an ordinary retry. Exhaustion is a typed `*PoolExhaustedError` naming the pool, its capacity, and the env var to widen — the daemon-level failure it replaces says none of that. Network lifecycle is two extra reconciler steps around the container: create-network before create-container (nothing can attach to a network that does not exist), remove-network after the container is gone, and the subnet is released only after the network is (releasing earlier could hand a still-in-use subnet to another instance). Networks are `Internal: true` — that is where egress default-deny is established. Operator-facing networking notes: `docs/developer/container-networking.md`. **Generation rotation** (`rotation.go` + `rotation_apply.go`, #813) is a SECOND pass (`ReconcileRotations`) rather than a branch in the core loop: the core loop converges a container toward its row, rotation converges a row SET toward a desired image, and one planner deciding between "start this container" and "supersede this generation" would be answering two different questions. Sequence, one pass each: begin (mint generation N+1 as `pending` + a fresh token) → create (create AND start in one step, unlike first boot — the gate must distinguish "still starting" from "started and exited") → promote/abort → switch → drain → retire. `planRotation` is pure over (desired row, generation rows, observed containers, now), and checks steps in REVERSE sequence order so a pass always finds the furthest-along state first — that is what makes a crash between any two steps resume rather than restart. The invariant: the old generation keeps serving until the new one passes its gate; an abort never touches it. Both waits are deadline-bounded (a gate with no deadline is not a gate — the rotation would hang open with the instance permanently mid-upgrade). Tokens are minted per generation, held in memory only (a stored token is one a DB leak hands out), taken-not-read so one token reaches one container, and revoked at RETIRE rather than switch — revoking during drain would fail the in-flight work draining exists to protect. Generation numbers are never reused, so a failed attempt consumes its number permanently. **Not wired into main.go yet** — nothing writes `plugin_containers` rows until the manifest v2 / loader work lands, and a loop with an empty desired set plus orphan cleanup is not something to enable early.
    caphealth/        — **MCP realignment (ADR-056, spec §7 health), #814.** Health PER CAPABILITY rather than per instance, to fix a defect rather than add a layer: in the v1.1 model one failing capability (classically one missing OAuth scope on one tool) marks the whole instance unhealthy, so every other capability it serves perfectly well stops being routed to — a small precise fault converted into a total outage that also hides which capability broke. Two layers, and the split is the whole idea. LIVENESS is instance-wide (container healthcheck + `server/discover`, both must pass — they answer different questions, and a container that is up with a wedged server passes the first and fails the second) and overrides everything, because nothing an unreachable instance last claimed can be trusted. CAPABILITY health is per `(profile, name)`; a fault narrows routing and nothing else. `Serves(capability)` is the routing question the audience dispatcher and event listener each ask for themselves. Silence is NOT a fault — an unknown capability serves, since treating "no signal" as "bad signal" would put every quiet plugin permanently out of service — but the prober seeds a healthy entry for every DECLARED profile so the registry reflects the whole surface, which is what lets a partial failure report as partial. It seeds only where no entry exists, so a fault recorded elsewhere (the host endpoint's `SetHealthState`, M17) survives a pass that had no opinion. States reuse `model.PluginHealthState` rather than coining a parallel vocabulary — the severity ordering, merge rule, and chip colors are already defined over those values in `internal/plugin/state`. The instance chip becomes a ROLLUP (worst of liveness + capabilities) written to `plugin_instances.health_state`, with the detail naming the failing capability. Per-capability health is deliberately NOT persisted: it is a live observation the prober re-derives, and a durable copy would be a second source of truth that is wrong every time the prober is between passes. Liveness verdicts AGE OUT (`NewRegistryWithStaleAfter`) because a stopped prober is otherwise indistinguishable from one that keeps finding everything healthy. Manifest-vs-discovery drift is a capability fault on the event-source profile, reported in both directions — attested-but-not-discovered is a capability the operator approved and is not getting; discovered-but-not-attested is a surface nobody signed for.
    inapptask/        — **MCP realignment (ADR-055, spec §6.4), #801.** The in-app channel's Request runs the SAME task lifecycle a plugin-routed Request uses, minus the MCP hop: a row in `mcp_tasks`, kind `channel_request`, with a NULL `server_id` meaning "resolved internally" (migration 0048 made the column nullable; a sentinel `mcp_servers` row would have put a fake, editable, deletable entry in the operator-visible server registry). One shape is not tidiness — it is what makes ONE resolution path, ONE audit record shape, and ONE restart story possible; two shapes would mean an operator's decision meant something subtly different depending on where they made it. `DecodeResolution` is that shared path and takes a task row without asking which route produced it. What is deliberately NOT shared is the poll loop: a plugin-routed task is polled because the host has no other way to learn the answer, while an in-app task is completed by an operator inside this process, so `Await` returns on a direct in-memory delivery (the spec's PollNow semantics — polling something whose answer arrives by function call would add latency for nothing). `internal/mcp`'s `PollScheduler` therefore skips internal tasks rather than spinning on a server that does not exist, and cancels them as a local row transition. The waiter is an optimization over the durable row and never a substitute: a host that dies loses the waiter and keeps the row, `Resumable` finds it, and `Rearm` restores immediate delivery. The v1.1 gRPC channel path stays live and untouched — this is the new route alongside it, and the old one is deleted at cutover (#22).
    hitl/             — **MCP realignment (ADR-055 / ADR-044, spec §4.1 + §6), #802.** Picks the ONE audience entry that will be asked a tool-initiated question, and settles the answer. Notify broadcasts, Request picks — an audience is a priority list, and asking two channels the same question would put two humans in a race whose loser is told their decision did not count. The new rule on top of the v1.1 audience is that the HOST decides which request kinds a channel may settle, from the assurance level that channel declares, and the rule is asymmetric on purpose: a weak channel may supply *information* (a wrong answer there is one the agent then acts on visibly) but may not grant *permission* (a forged approval is indistinguishable from a real one after the fact). Weak does not fail the request — it is skipped and the next entry is tried, which is what keeps low-assurance channels useful rather than merely decorative. Enforcement is host-side before `channel/request` is issued; the kind is still SENT so a channel can render a permission prompt differently from a form, but a rule enforced by the party it constrains is not a rule. Every skip is recorded with a typed reason rather than logged and forgotten — "the third channel answered" is only evidence alongside why the first two did not, which is what the §6.6 decision record needs. All skip paths are survivable because none of them delivered anything: a notify-only server that declares the extension errors on `channel/request` and the audience moves on (the extension doc's case C), an unreadable capability declaration resolves nothing rather than being guessed upward, and a declared major version this host cannot read is refused rather than attempted. `ErrNoEligibleEntry` is reachable only when an operator disabled the in-app fallback, since the synthetic entry is `authenticated` and settles both kinds — a configuration fault, and worth failing loudly instead of leaving a request nobody is ever asked. Routing ends when the ask is durable and addressable (an `mcp_tasks` row, kind `channel_request`); from there a plugin-routed task is polled by `internal/mcp`'s PollScheduler and an in-app task is delivered by function call, both terminating on the same row. `Complete` is the exactly-one point: the row's CAS (ADR-038) arbitrates, so a poller observing a server-side completion and an operator clicking in the UI contend on the same UPDATE and the loser gets `ErrAlreadyResolved` rather than overwriting a decision. Plugin-routed resolution latency is bounded by the poll interval until poll-on-signal (`AuthorizeActor` as a PollNow hint, spec §6.4 Amendment 1) lands with the host endpoint in milestone #17.
    decision/         — **MCP realignment (ADR-055 / ADR-046, spec §6.6), #803.** Decision records for tool-initiated HITL: what a human was asked mid-execution, who answered, through which channel, and how strongly that channel knows the person it names. The spec calls the two additions "step types" *alongside* `approval_request` / `feedback_request`, but that is an analogy to their shape, not to where they live — `RecordToolPermissionRequest` / `RecordToolInputRequest` are deliberately NOT `model.StepType` values, and a test pins that. ADR-046 splits the tables on one line: `run_steps` is replayed into the model's context, so anything written there is something the agent reads. Making these StepTypes would make them eligible for replay *by construction*, leaving the purity test guarding a door already open — and would hand a server a route for smuggling text into context through an operator's own answer. They go to `plugin_audit_events`, which gained a nullable `run_id` (migration 0049, `ON DELETE SET NULL` like `plugin_instance_id`: deleting a run must not delete the evidence a human approved something during it). The record is wide because "an approval happened" is not oversight evidence — each field exists because its absence would let two materially different events produce identical rows: assurance without an actor says a strong channel was used but not by whom; an actor without a `LinkMethod` is a name the channel asserted, and whether the host could tie it to a Gleipnir user is the difference between evidence and hearsay; classification separates consent from data entry, which carry different authority and different answering roles; the considered-and-skipped list (fed by `hitl`'s typed skip reasons) is *why this channel*, since a decision made by the third audience entry only means something alongside why the first two did not make it; and the outcome distinguishes a refusal from a silence — both leave the request unfulfilled, only one involved a human. `OutcomeReplayedAfterTTL` is its own outcome rather than a second "answered" because no human acted at that moment, and reading it as a fresh approval would be reading one consent as two. Severity is `info` except: timeouts and cancels are `warning` (a run stalled on people), and so is a **permission** settled by an actor the host could not link to a user — that is the shape a forged approval takes, and an operator scanning the feed should not have to open every record to find it. Exactly one record per request, written at settlement: the request is already durable in `tool_input_requests`, so a separate "we asked" row adds nothing, while a second row per request would double-count approvals in any export that counts them. The in-process duplicate guard is claim-before-insert / release-on-failure (claiming after would let two concurrent settlements both write; releasing on success would refuse a legitimate retry), and it is a backstop rather than the mechanism — the durable guarantee is the caller's single terminal transition under the ADR-038 CAS. Read side: `Decode` refuses an unreadable row instead of returning an empty record, since an empty record reads as "nobody acted"; `GET /api/v1/runs/:runID/decisions` serves them.
    egress/           — **MCP realignment (ADR-056, spec §7 networking), #812.** The host-side forward proxy that turns manifest-declared, admin-consented egress grants into runtime enforcement. Default deny is already established by topology (#811's `Internal: true` per-instance networks); this package is the one way OUT. Design record with the rejected alternatives: `docs/developer/egress-containment.md` — firewall rules need `CAP_NET_ADMIN` in the host netns, which is a privilege escalation to enforce a containment policy and is invisible to rootless Podman's userspace networking anyway; DNS filtering is bypassed by connecting to an IP literal, so it is advice rather than a control. A CONNECT proxy matches the NAME the admin consented to (rotating CDN addresses are a non-issue, and an IP allowlist would admit every other tenant on a shared address), tunnels TLS without terminating it, and can say what it refused. The **east-west trap** is the sharp edge: the proxy sits on every instance network *and* has ordinary egress, so a naive one would dial a sibling's MCP endpoint on request and undo the isolation through the component meant to enforce it. It therefore refuses IP-literal targets outright and refuses any target *resolving* into private/loopback/link-local/multicast/unspecified space — checked twice, once at decision time and once in `dial`, because between them is a window a rebinding resolver could use. Instance identity is `conn.LocalAddr()`, the gateway the connection arrived on: the kernel picks it from the arrival interface, so a plugin cannot claim another instance's grants (the peer address would be forgeable; a `Proxy-Authorization` token would only be as honest as the plugin). Grants come from `plugins.manifest_snapshot` — the *consented* copy — so ADR-045's material-change block means a plugin cannot widen its own egress by shipping an update. `egress: []` grants nothing and is a real value; wildcards are a single leading `*.` stored **with** the dot, so `*.slack.com` admits `api.slack.com` and refuses both `slack.com` and `evil-slack.com`. Every refusal is a WARN log + `gleipnir_plugin_egress_denied_total{reason}` + an audit event, because silent denial is undebuggable; allows are counted but not audited per-connection so the denials stay readable. `StripProxyEnv` runs before `ProxyEnv` on every create — an inherited `NO_PROXY` from a base image is a hole while every other line still looks correct.
    logcapture/       — **MCP realignment (ADR-056, spec §7 logs), #816.** Streams a plugin container's stdout/stderr into the host's structured logger. It is the FALLBACK channel and says so on every line (`correlated: false`): correlated logging rides the host endpoint's `Log` method, and ADR-047 chose that over stdout because stdout has no ordering or attribution guarantees, so a line arriving on it cannot be tied to the work that produced it. What lands here is what never reaches structured logging — pre-handshake panics, misbehaving images, a process killed before it said anything. Lines carry plugin/instance/**generation**, the last because during a rotation two containers for one instance are alive at once and "which one said this" is the question. `Decode` handles both framings the runtime can produce (8-byte multiplexed header for a TTY-less container, raw for a TTY one) by SNIFFING rather than being told: a plausible header is a known stream byte, three zero bytes, and a length that is not absurd. The sniff is deliberately conservative because guessing wrong on raw output corrupts the first line of a crash message, which is the line that matters most. Bounded on both axes — a token bucket per instance (50 lines/s, burst 200) and an 8 KiB per-line cap, since one enormous line is the same denial-of-service as many. Drops are LOUD: a periodic WARN naming the count plus `gleipnir_plugin_container_log_dropped_total`, because a truncated log that says nothing about being truncated reads as the container having gone quiet. A per-instance ring of the last 50 lines backs `StartupFailureDetail`, the "why won't my plugin start" surface — a container that exits before it is healthy leaves nothing behind except what it printed, and the detail is bounded to the last few lines because a health chip is not a log viewer. `Forget` clears ring + limiter + drop counter on instance removal so a re-created instance does not inherit an exhausted bucket.
    resources/        — **MCP realignment (ADR-056, spec §7), #815.** Turns declared and operator-set limits into enforced cgroup caps, and reports what containers actually consume. The shift it embodies: v1.1 SAMPLED RSS from `/proc` and alerted, which is observation; a cgroup cap is enforcement — the kernel refuses the allocation rather than Gleipnir noticing afterwards. `Resolve` applies admin override → manifest → host default, **per field rather than per layer**: an admin who caps memory without an opinion about CPU must not silently discard the author's CPU figure and fall all the way back to the default, since each number is a separate judgement. The override wins because an operator running the host has better information than an author who has never seen it — the manifest value is an estimate, the override is the person who will be paged. The resolved `Source` travels with the values because "why is this plugin capped at 128 MiB" has three possible answers and an operator should not have to guess. Defaults are REAL caps (256 MiB / 500m), not "unlimited": an uncapped container on a homelab host is one plugin away from an OOM that takes Gleipnir with it, and the point of the shift is that the failure lands on the plugin. A NULL limit column therefore means "nobody specified", never "no limit". `FromManifestMiB` rejects values the runtime cannot enforce rather than clamping them — silently raising a typo'd 1 MiB to something workable would make the consent screen say one thing and the container do another. `Collector` polls the stats API into `gleipnir_plugin_container_*` gauges labelled `(plugin, instance)` to match the v1.1 RSS gauge, so a dashboard survives the cutover with only the number's source changing; instances that vanish have their gauges DELETED, because a stale gauge reads as a running container using memory and is exactly what an operator would act on. `ObserveExit` reports only on the runtime's OOM flag, never on a non-zero exit: a plugin that crashed on its own is a different fault with a different fix, and conflating them sends an operator to raise a limit that was never the problem. An OOM produces both a capability-level health fault (routing) and an audit event (the record), and the detail names the limit because the fix is almost always to raise it.
    reconciler/discover.go — **manual-mode discovery (ADR-056 spec §7 posture 3), #817.** Manual mode is first-class, not degraded: the operator declares plugin containers in their own compose file and Gleipnir discovers by label, health-checks, and wires into the MCP client without ever writing to the socket. The "never writes" half is enforced by `container.ReadOnlyRuntime` (every write returns `ErrManualModeWrite`), not by this code remembering to behave — a posture guaranteed by caller discipline is one refactor away from being untrue, and the test asserts a full `DiscoverPass` performs zero socket writes through a counting wrapper. `Discover(desired, observed)` is pure over its inputs, like `planFor`, so the whole state table is testable without a socket. Five states, each named because every one of these failure modes is silent by nature: `matched`; `declared_but_not_found` (a typo'd label looks identical to not having started it); `found_but_not_installed` (a stale container Gleipnir will not touch, since in manual mode nothing is Gleipnir's to remove — naming it is all it can do); `wrong_generation` (**the plugin running is not the plugin that was approved**); and `ambiguous`, where Gleipnir refuses to guess which of several claimants is authoritative because routing to the wrong one is indistinguishable from routing to the right one until something goes wrong. A desired row that tracks no generation cannot be contradicted by one. Output is sorted so an operator comparing two passes sees a diff only where something changed. Operator docs, including the reference compose file and the four silent misconfigurations: `docs/developer/manual-mode.md`.
    reconciler/gc.go  — **image GC + network/token cleanup (ADR-056 spec §7), #818.** Level-triggered like every other pass here: no delete queue and no "pending cleanup" state, just "what is unreferenced right now" reclaimed a bounded slice at a time, so a crashed pass costs one interval and a missed reclaim is found again. A SEPARATE pass from `ReconcileOnce` and meant for a SLOWER cadence — convergence is latency-sensitive (an operator who starts an instance wants a container within one interval) while nothing gets worse for a few minutes because a dead image is still on disk. Image safety is three layers, each because the next is not sufficient alone: the list query excludes every digest a live generation pins — **including a `draining` one, the case that matters**, since the old generation keeps serving until the new one passes its gate and its image is in use in exactly the window it looks stalest; a reference re-check immediately before the socket call closes the gap a rotation starting mid-pass would open (and reports when it fires, so the race is observable rather than inferred); and the daemon's own "in use" refusal catches Gleipnir's records simply being wrong, which is why removal is never FORCED — a forced removal untags an image a container still uses, leaving a running plugin on an image nothing can name, the exact state a digest pin exists to prevent. Image-then-record ordering: dropping the accounting row first would leave bytes on disk that nothing would ever reclaim again. Bounded per pass because image removal is the slowest thing this package asks a daemon to do, and `ImagesDeferred` reports what was skipped — a bounded pass that says nothing about its backlog reads as "there was nothing else to do". Subnet release is a BACKSTOP for what `removeNetwork` never got to do, and its condition is conjunctive: releasable only when no desired row claims the instance AND no managed network survives, because handing a subnet to another instance while the old network is up produces an overlap the runtime refuses at create time — a clean teardown turned stuck. `orphanedSubnets` is pure over its inputs like `planFor`/`Discover`, sorted so two passes over an unchanged world read identically. Token hygiene TOMBSTONES the hash (`purged:<id>`) rather than deleting the row: deleting would discard the rotation history an operator reads, and deleting the highest-numbered row would let the next rotation reuse a generation number a stale container may still be labelled with. The 24h retention window exists because a revoked token is briefly still evidence — a host RPC that arrived just before revocation is correlated by that hash, and purging on the instant would make the end of a generation's life unattributable, which is the window a rotation's problems show up in. Manual posture reports and removes nothing (`Applied:false`, and `ReadOnlyRuntime.ImageRemove` makes it structural rather than a remembered check) — **except tokens**, which purge in both postures: manual mode constrains what Gleipnir does to the OPERATOR's resources, and a hash Gleipnir minted in its own database is not one of those. Operator docs: `docs/developer/container-gc.md`.
    substrate/        — **real-daemon integration suite (ADR-056 §7/§15), #820.** No production code: a `doc.go` so the package exists for `go list` and the gate scoper, plus one build-tagged test file. Every other test in this milestone runs against `container.Fake`, which executes the SAME `ValidateCreate`/`ValidateCreateNetwork` the real runtime does — so a Fake-based assertion about a rejection is an assertion about the actual rule, not a double's approximation. What a Fake cannot answer is whether the DAEMON agrees: that a network created `Internal:true` really has no route out, that a subnet the allocator carved is one the daemon accepts, that an image GC believes unreferenced is one the daemon will delete (and that it REFUSES while a container holds it), and that a container on one instance network genuinely cannot reach another's. The isolation assertion runs a real probe container rather than dialing from the test process, because the test process is on the host and the host reaches almost everything — proving nothing about what a plugin can reach from inside its own network. Gated by the `substrate` BUILD TAG rather than a runtime `t.Skip`: a skip reads as a passing test in every log that only counts failures, so the one suite whose whole job is "we checked against a real daemon" would be silently absent exactly where nobody is watching. Cleanup removes by LABEL, not by an accumulated id list — an id list is precisely what a panic loses. `make ci-local` never runs it (needs a socket and a pre-pulled probe image) and says so in its summary rather than staying quiet about a lane it skipped; CI runs it on rootless Podman, required on PRs that reach the substrate packages and scheduled nightly otherwise, bounded at 15 minutes. Which PRs reach it is answered by `scripts/ci-local-scope.sh` — the same scoper the local gate uses — so there is no second path list in YAML to drift from the first. Operator docs: `docs/developer/container-substrate.md`.
    container/        — **MCP realignment (ADR-056, spec §7).** Typed wrapper over the Moby client. `Runtime` embeds a narrow `ImageRuntime` (`ImageLoad` + `ImageInspect`) so the installer can load an image without being handed the ability to start a container. `ImageLoad` drains the daemon's progress stream to completion rather than parsing it — what was loaded is established afterwards by inspecting the digest the caller already expects, a yes/no question with no parser. `ReadOnlyRuntime` treats `ImageLoad` as a write (fails closed with `ErrManualModeWrite`) and `ImageInspect` as a read (delegates), which is what lets manual posture still verify an operator-loaded image against a manifest pin.
    oauth/            — host-side OAuth2 orchestration for plugin instances (spec §9.1/§9.2, issue #224). `Manager.BeginAuthcode` builds an `oauth2.Config`, encodes an HMAC-signed state envelope (HKDF-derived subkey off `GLEIPNIR_ENCRYPTION_KEY`, info `"gleipnir-oauth-state-v1"`), records a one-time nonce, and returns the provider authorize URL. `Manager.HandleCallback` verifies + consumes the state envelope, exchanges the code via `cfg.Exchange`, persists the token, and emits `plugin_oauth_issued`. `Manager.BeginClientcred` runs the client-credentials grant synchronously. `DBStore` encrypts `StoredCredentials` (strategy + endpoints + token) into `plugin_instances.credentials_encrypted`; `EncryptFunc`/`DecryptFunc` are injected at construction time to avoid an `internal/admin` import cycle (the admin OAuth handler imports this package). `SaveToken` runs a load→modify→save CAS retry (3 attempts, no sleep) gated by a per-instance mutex (`locks.go`), and skips the write when a concurrent refresher already stored a fresher token. `NewTokenSource` wraps `oauth2.Config.TokenSource` / `clientcredentials.Config.TokenSource` in a persisting decorator that calls `SaveToken` + `EmitRefreshed` on rotation and `MarkRefreshFailed` on inner error — `MarkRefreshFailed` drives the instance to `PluginHealthStateUnhealthy` for #228's "Re-authorize" UI. `RefreshScanner` mirrors `internal/timeout/scanner.go`: every `GLEIPNIR_OAUTH_REFRESH_INTERVAL` it queries `ListPluginInstancesWithExpiringCredentials` for rows expiring within `GLEIPNIR_OAUTH_REFRESH_LEAD`, builds the TokenSource, and calls `.Token()` (the wrapper handles the actual refresh + persist). The scanner skips authcode-strategy rows when `public_url` is unset. The callback path `/api/v1/admin/plugins/oauth/callback` is registered OUTSIDE the `requireAuth` middleware (browser arrives from the OAuth provider with no Gleipnir session) — the HMAC state envelope is the sole auth primitive, mirrors ADR-034.
```
