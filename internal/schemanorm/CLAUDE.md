# internal/schemanorm — design notes

Moved from the root CLAUDE.md `Key packages` entry (2026-07-31); loads when working in this package.

stdlib-only leaf package (no internal imports, mirrors `toolregistry`): BYTE-LEVEL normalization of JSON Schema tool-input documents, nothing more. `Normalize(raw json.RawMessage)` decodes with `UseNumber`, enforces three independent bounds (`Limits`, defaults `MaxBytes` 1 MiB / `MaxDepth` 64 / `MaxNodes` 10,000; `<=0` means "use the default", there is no unlimited mode), and re-emits with object keys recursively sorted and `SetEscapeHTML(false)`. That is the entire transformation — no `$ref` resolution, no `$defs` stripping, no `allOf` handling, no identity-keyword stripping, no dialect gate. Nothing is inlined, merged, wrapped, or relocated. Because nothing is ever duplicated, output size is bounded by roughly 2x input size (`encoding/json` always escapes U+2028/U+2029 to a 6-byte `\u2028`/`\u2029` ASCII sequence regardless of `SetEscapeHTML` -- measured exactly 2.000x at 1 MiB), a fixed constant factor rather than an unbounded amplification, so there is no separate output-byte bound (unlike a prior, ref-resolving version of this package). The safety argument is one line: JSON object members are unordered (RFC 8259), and no JSON Schema keyword depends on member order, so reordering cannot change what any validator accepts — this package claims nothing stronger than that. This is the package's THIRD design: the first two attempted bounded `$ref` inlining and `allOf` merging (then a "never merge" `$ref`-substitute-or-`allOf`-wrap redesign), and three consecutive security reviews each closed one widening mechanism and found a new one — keyword relocation across a schema-object boundary, then `$ref` mis-resolution (`$id` base URIs, percent-encoded pointers), then narrowing-through-wrapping not composing under negation plus `$schema` being position-dependent. The root cause was the same each time: JSON Schema has keywords whose meaning depends on WHERE THEY SIT, and any structural transformation moves something. This package now performs no structural transformation, closing that whole defect class by construction rather than by finding and patching one more mechanism. A decode-and-re-emit round trip through `encoding/json` DOES change meaning in exactly three ways, and this package REJECTS all three rather than accommodating them: (1) duplicate object keys — `encoding/json`'s `Decode` is silently last-wins, so `{"a":1,"a":2}` loses a member; caught by a token-level `json.Decoder` scan at every object depth (`ErrDuplicateKey`), because a plain `Decode` into a generic tree cannot detect it after the fact. (2) invalid UTF-8 / lone UTF-16 surrogate escapes — `encoding/json` silently substitutes both with U+FFFD at decode time (verified empirically), so the check runs directly against the raw input bytes before any decoding, the only point the original bytes are still inspectable (`ErrInvalidUTF8`). (3) numeric re-rendering — already closed by `UseNumber`, which retains the original literal text verbatim (`1.500`, `1e400`, `-0`, and 30-digit literals all round-trip byte-for-byte; regression rows in `schemanorm_test.go`). `Normalize(Normalize(x)) == Normalize(x)` byte-for-byte (there is only one sorted order, so normalizing twice is a no-op). Typed errors (`*Error{Kind,Pointer,Detail}` + sentinels, `errors.Is`/`errors.As`) survive from the prior design for `ErrInvalidJSON`/`ErrByteSizeExceeded`/`ErrDepthExceeded`/`ErrNodeCountExceeded`, plus the two new sharp-edge sentinels above; `ErrInvalidSchema`/`ErrExternalRef`/`ErrRefCycle`/`ErrRefNotFound`/`ErrUnsupportedDialect`/`ErrOutputBytesExceeded` are gone along with the transformation logic they existed to report on. A seeded randomized property test (`property_test.go`, fixed seed printed on failure) generates random schemas with object keys inserted in deliberately SHUFFLED (not sorted) order, compiles both the as-generated bytes and `Normalize`'s output with `santhosh-tekuri/jsonschema/v6`, and validates random probe instances against both, failing on ANY disagreement in EITHER direction — this package must now be *exactly* equivalent to its input, so a narrowing is as much a bug as a widening. ADR-059 / spec §10 step 1 — **not yet wired to any call site**; the future consumer is `internal/mcp` `RefreshTools`, which today compares raw schema bytes (#735). `$ref` resolution and `allOf` flattening for LLM-provider presentation now belong entirely to spec §10 step 2 (per-provider translation, `internal/llm`), where lossiness/widening is the declared, accepted policy because exact enforcement (§10 step 3) runs against the untransformed, stored schema.
