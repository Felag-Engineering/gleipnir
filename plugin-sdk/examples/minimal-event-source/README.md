# minimal-event-source

The smallest possible `io.gleipnir/events` plugin: one event kind
(`example.ping`), served over `plugin-sdk/events.Handler`. If you are
writing your first Gleipnir event-source plugin, start here.

Unlike `minimal-tool/` (a go-plugin subprocess launched over the live v1.1
gRPC handshake), this example serves an ordinary `net/http` handler on a
port — the shape a containerized MCP-realignment plugin (ADR-053) actually
runs as. It is a `main()` that blocks serving HTTP, not something the test
suite executes directly; the tests exercise `events.Handler` in
`plugin-sdk/events` itself, and here only check that this example's own
declarations agree with each other.

## What this example demonstrates

- Declaring event kinds once (`eventKinds` in `main.go`) and handing that
  slice to `events.NewHandler` — the same slice `events/discover` renders,
  so the running handler cannot drift from what it advertises.
- The shape of a `manifestv2.Manifest` declaration in Go (`manifest.go`),
  including the `profiles.event_source` profile and an `event_kinds` entry.
- A canonical `manifest.yaml` committed alongside the source and kept in
  sync with `manifest.go` by `TestManifestYAMLIsCanonical`.
- `TestManifestEventKindsMatchHandlerKinds`: proof that the kinds
  `manifest.yaml` attests (what an admin reviews at install time) match the
  kinds the running handler actually discovers — the drift `events/discover`'s
  doc comment warns a plugin's manifest and its live discovery response must
  not fall into.

## Layout

```
minimal-event-source/
  main.go            — eventKinds + events.Handler wiring; entry point for the plugin binary
  manifest.go         — pluginManifest variable (source of truth for metadata)
  manifest.yaml       — canonical YAML projection of manifest.go (generated, not hand-written)
  manifest_test.go    — TestManifestYAMLIsCanonical + TestManifestEventKindsMatchHandlerKinds
  go.mod              — per-example module; resolved by the repo-root go.work
```

## Manifest

`manifest.go` is the source of truth. `manifest.yaml` is its canonical
projection — generated by `manifestv2.Marshal`, never written by hand. If you
edit `manifest.go`, regenerate the YAML with a throwaway helper (deleted
before committing — `manifest.yaml` is the artifact that lands in the repo),
following the same steps as `minimal-tool/README.md`'s "Manifest" section but
using `manifestv2` instead of `manifest`:

```go
//go:build ignore

package main

import (
	"fmt"
	"os"

	"github.com/felag-engineering/gleipnir/plugin-sdk/manifestv2"
)

func main() {
	b, err := manifestv2.Marshal(&pluginManifest)
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	os.Stdout.Write(b)
}
```

```sh
go run gen_manifest_local.go manifest.go > manifest.yaml
rm gen_manifest_local.go
go test .
```

## Run

`main()` calls `http.ListenAndServe` directly — this example needs no fake
host or go-plugin handshake, since `io.gleipnir/events` is an ordinary MCP
extension served over streamable-HTTP. Running the binary starts a real
server on `:8080` and emits an `example.ping` event every 30s; point a
`plugin-sdk/events`-round-trip-style client at it (or curl `server/discover`
and `events/discover` directly) to see the wire shapes in `docs/developer/
extension-io-gleipnir-events.md` §4 and §6 in practice.

## Using outside the monorepo

Same two options as `minimal-tool/README.md`'s "Using outside the monorepo"
section: a local `go.work` pointing at `plugin-sdk/`, or a `replace`
directive in this example's `go.mod`.
